## From checkout to Bambu Studio

Cloudflare Workers sit behind the storefront. They validate order payloads,
verify identity and Turnstile, read pricing on the server, calculate shipping,
create an idempotent Stripe Checkout session and write the order to Firestore.
A signed Stripe webhook updates its payment status, while Stripe sends the
customer a receipt. The public site is deployed automatically from GitHub to
Cloudflare at `cubi-3d.com`.

I deliberately store the cleaned SVG and design instructions, not a heavy
generated model. When I open an order, the admin panel reconstructs the exact
3D preview and generates the 3MF only when I need to manufacture it. That keeps
checkout fast and moves the expensive geometry work onto the machine doing the
production.

The 3MF exporter builds the board, snap-fit pieces, logo inlay and tile icons as
properly separated colour components, embeds the customer's configuration as
metadata and produces a file I can take straight into Bambu Studio. Reaching
that point took repeated slicer tests: the browser preview could not tell me
when an icon had become empty geometry or when Bambu would interpret two parts
incorrectly.

## The private production studio

The admin panel is where the web product becomes a small manufacturing system.
It gives me a live order queue, payment badges, an order-detail viewer, 3MF and
design-package exports, and a kanban flow from new order through printing,
shipping and delivery.

The same workspace manages product availability, the live filament palette and
society crest approvals. Firebase Authentication protects the interface, while
Firestore rules and server-issued admin claims protect the data independently
of what the browser displays.

## Building the route to market

I also built the first customer-acquisition workflow around the product. My
scrapers collected society names, contact addresses and crests across Irish
universities. Inside the admin panel I can review or replace a crest, run it
through the same converter and publish a personalised page at `/for/<slug>`.

That means an outreach email can link to a real preview already carrying the
recipient's identity. Approved contacts sync to a Google Sheet with deduplication,
signed unsubscribe links and a server-side do-not-contact list, so re-scraping
cannot quietly add an opted-out society again.

## What Cubi became

Cubi brought together industrial design in Fusion, browser-based image
processing, real-time 3D graphics, secure payments, backend rules, deployment,
outreach and additive manufacturing. I used GitHub for the development history
and deployment flow, and Obsidian as the project's source of truth while Claude
and Codex helped me reason through design and engineering problems.

**Tools used:** Claude, Codex, Stripe, Bambu Studio, Cloudflare, GitHub and VS
Code, alongside React, TypeScript, Firebase, WebAssembly, Fusion and Obsidian.

More importantly, it changed how I build. I stopped judging progress by whether
a feature looked finished and started judging it by whether a real customer
could use it, pay for it, and receive the physical result. Cubi is now live and
working. The mistakes are not an awkward preface to that result; they are how I
got there.
